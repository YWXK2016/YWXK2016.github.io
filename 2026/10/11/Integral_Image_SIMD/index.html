积分图计算——使用SIMD指令集优化

在积分图（Integral Image）的原理与三种实现中，实现了三种积分图的计算方法，但和OpenCV的积分图计算接口相比，速度还存在一定差距。这里将使用SIMD指令集来优化积分图的计算。

一、SIMD指令集

SIMD（Single Instruction Multiple Data）指令集，即单指令多数据流，是一种采用一个控制器来控制多个处理单元，同时对一组数据（又称“数据向量”）中的每一个分别执行某项操作，从而实现空间上的并行性的技术。SIMD指令集可以显著提高计算性能，但需要硬件支持。常见的SIMD指令集有SSE、AVX等。

  • SIMD：Single Instruction Multiple Data，单指令多数据。它描述的是“一条指令同时处理多个数据”的计算方式。

  • SSE：Streaming SIMD Extensions，Intel 在 x86 上推出的 SIMD 指令集，主要使用 128 位寄存器 XMM。

  • AVX：Advanced Vector Extensions，是 SSE 之后的进一步扩展，主要使用 256 位寄存器 YMM，后来还有 AVX-512 使用 512 位寄存器。

三、使用SIMD指令集优化积分图计算

在积分图（Integral Image）的原理与三种实现一文中方法三是基于方法二的优化，因此这里只对手动实现的方法一和方法三使用SIMD指令进行优化，包括SSE指令集和AVX指令集优化。

1.使用SSE指令集优化积分图计算方法一

水平前缀和：将每行分成 4 个 float 的块，用 _mm_slli_si128 和 _mm_add_ps 在块内并行计算前缀和，再用 prev_sum 处理块间累加依赖。

垂直累加：列之间独立，直接用 _mm_add_ps 一次处理 4 列，大幅提升吞吐量。

2.使用AVX指令集优化积分图计算方法一

AVX指令每次处理 8 个 float。首先利用置换指令分别构造偏移 1、2、4 个元素的向量，并把越界位置清零，通过逐级相加完成块内前缀和；然后加上上一块的累计值。垂直阶段同样每次累加 8 列，末尾不足 8 列的部分仍使用标量循环。

3.使用SSE指令集优化积分图计算方法三

方法三把水平前缀和与上一行积分值的累加合并到同一次行扫描中。SSE 每次处理 4 个输入值，先计算向量块内的前缀和，再加上前一块传来的行累计值，最后与上一行对应的积分值相加得到输出；当前块末尾的累计值会广播后传给下一块。首行没有上一行数据，因此只累加行前缀；不足 4 个元素的尾部使用标量循环补齐。

4.使用AVX指令集优化积分图计算方法三

AVX指令每次处理 8 个 float，在向量内部通过偏移 1、2、4 个元素的置换与加法构造前缀和，再接上前一向量块的行累计值，并加上上一行的积分结果。首行跳过垂直累加，行末不足 8 个元素则回退到标量计算。

五、问题分析

1.为什么使用AVX指令计算块内前缀和时不使用SSE指令类似的方法？

在使用SSE指令对方法一做加速时，计算水平方向的块内前缀和使用了两步移位加法。

假设__m128类型数据v中从高地址到低地址存储的数据分别为d3，d2，d1，d0，那么计算块内前缀和的过程如下：

数据和操作 地址3
(高地址)		 地址2 地址1 地址0
(低地址)
v d3 d2 d1 d0
v左移1个float d2 d1 d0 0
v1 d3+d2 d2+d1 d1+d0 d0
v1左移2个float d1+d0 d0 0 0
v2 d3+d2+d1+d0 d2+d1+d0 d1+d0 d0

那从低地址到高地址，块内前缀和v2存储的数据就分别为：d0，d0+d1，d0+d1+d2，d0+d1+d2+d3。

在计算水平方向的块内前缀和时，SSE指令同时处理4个float数据，可以使用两步移位加法，而AVX指令同时处理8个float数据，是不是可以类似的使用三步移位加法？代码如下：

假设__m256类型数据v中从高地址到低地址存储的数据分别为d7，d6，d5，d4，d3，d2，d1，d0，那么上面计算块内前缀和的过程是不是也像这样？

数据和操作 地址8
(高地址)		 地址7 地址6 地址5 地址4 地址3 地址2 地址1
(低地址)
v d7 d6 d5 d4 d3 d2 d1 d0
v左移1个float d6 d5 d4 d3 d2 d1 d0 0
v1 d7+d6 d6+d5 d5+d4 d4+d3 d3+d2 d2+d1 d1+d0 d0
v1左移2个float d5+d4 d4+d3 d3+d2 d2+d1 d1+d0 d0 0 0
v2 d7+d6+d5+d4 d6+d5+d4+d3 d5+d4+d3+d2 d4+d3+d2+d1 d3+d2+d1+d0 d2+d1+d0 d1+d0 d0
v2左移4个float d3+d2+d1+d0 d2+d1+d0 d1+d0 d0 0 0 0 0
v3 d7+d6+d5+d4+d3+d2+d1+d0 d6+d5+d4+d3+d2+d1+d0 d5+d4+d3+d2+d1+d0 d4+d3+d2+d1+d0 d3+d2+d1+d0 d2+d1+d0 d1+d0 d0

实际上，这个所谓的“三步移位加法”是不行的，因为SSE指令中_mm_slli_si128(a, N)是将128位的a整体左移N字节(Nx8位)，低位补0。_mm256_slli_si256是128位lane内移位，不能跨lane。

设输入v = [d0, d1, d2, d3 | d4, d5, d6, d7]（| 是 lane 边界，从低地址到高地址），上述代码实际的计算过程如下：

数据和操作 实际操作 低lane 高lane
v [d0, d1, d2, d3] [d4, d5, d6, d7]
v左移1个float 每个 lane 移 1 float [0, d0, d1, d2] [0, d4, d5, d6]
v1 [d0, d0+d1, d1+d2, d2+d3] [d4, d4+d5, d5+d6, d6+d7]
v1左移2个float 每个 lane 移 2 float [0, 0, d0, d0+d1] [0, 0, d4, d4+d5]
v2 [d0, d0+d1, d0+d1+d2, d0+d1+d2+d3] [d4, d4+d5, d4+d5+d6, d4+d5+d6+d7]
v2左移4个float 每个 lane 移 4 float [0, 0, 0, 0] [0, 0, 0, 0]
v3 [d0, d0+d1, d0+d1+d2, d0+d1+d2+d3] [d4, d4+d5, d4+d5+d6, d4+d5+d6+d7]

可以看到，v3中高lane的值和预期的[d0+d1+d2+d3+d4, d0+d1+d2+d3+d4+d5, d0+d1+d2+d3+d4+d5+d6, d0+d1+d2+d3+d4+d5+d6+d7]不一样。

2.为什么AXV指令加速时不使用_mm256_shuffle_ps指令更新prev_sum？

使用SSE指令加速时，更新prev_sum的方法如下：

使用AVX指令加速时，这样更新prev_sum可以吗？

语法上没有问题，但是它不会把整个256位里的8个float都广播成v4[7]。AVX的_mm256_shuffle_ps是在两个128-bit lane内分别做shuffle，不能跨lane选元素。

执行_mm256_shuffle_ps(v4, v4, _MM_SHUFFLE(3, 3, 3, 3))后的结果是prev_sum = {d3, d3, d3, d3, d7, d7, d7, d7}。

3.为什么有些AVX指令不能跨lane操作？

  • 兼容性：AVX 是 SSE 的 256 位扩展，lane 结构让旧指令能自然升级。

  • 硬件成本：跨 lane 需要交叉开关，增加延迟、面积、功耗，而大多数操作不需要。

  • 编程模型：lane 独立是 SIMD 并行性的基础，跨 lane 操作应显式用 permute 类指令表达。

  • 性能权衡：把跨 lane 做成少数专用指令，比让所有指令都支持跨 lane 更划算。
