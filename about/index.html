智能指针

基于MSVC 2017的源码实现，std::shared_ptr、std::weak_ptr和std::unique_ptr这三种智能指针的设计理念和内存布局有显著差异。

🧬 std::shared_ptr 与 std::weak_ptr：共享所有权的基石

shared_ptr 和 weak_ptr 的核心是 控制块 (Control Block)，它独立于被管理的对象，负责管理共享状态。

  • 核心组成：shared_ptr 继承自 _Ptr_base 基类，主要包含两个成员：
    • _Ptr：指向被管理对象的原始指针。
    • _Rep：指向控制块的指针，这是实现共享与弱引用的关键。
  • 控制块 (_Ref_count_base)：
    • 引用计数：包含两个原子变量：
      • _Uses：强引用计数，追踪有多少个 shared_ptr 共享资源。当变为0时，资源被销毁。
      • _Weaks：弱引用计数，追踪有多少个 weak_ptr 观察资源。当变为0时，控制块自身被销毁。
    • 虚函数接口：定义了两个核心虚函数：
      • _Destroy()：负责销毁被管理的对象。
      • _Delete_this()：负责销毁控制块自身。
    • 线程安全：所有引用计数的增减都通过原子操作完成，确保了在多线程环境下对引用计数操作的安全性。
  • 控制块的派生体系：MSVC 根据构造方式派生出不同的控制块类。
    • _Ref_count：通过 new T 直接构造。控制块内只存一个指向对象的指针，对象和控制块的内存是分离的。
    • _Ref_count_resource：支持自定义删除器。使用 _Compressed_pair 来存储删除器和资源指针，以应用空基类优化 (EBO)。
    • _Ref_count_resource_alloc：在支持自定义删除器的基础上，额外支持自定义分配器。
  • make_shared** 的优化**：make_shared<T>() 会创建一个特殊的控制块（如 _Ref_count_obj），它将对象的内存直接包含在控制块内，实现一次内存分配，比直接构造 shared_ptr 的两次分配更高效。
  • weak_ptr** 的实现**：weak_ptr 与 shared_ptr 拥有相同的内存模型，同样继承自 _Ptr_base。它通过控制块的 _Weaks 计数来观察资源。
    • lock()** 函数**：是获取资源的主要方式。它会原子性地检查 _Uses 计数。
      • 若 _Uses > 0，则将其原子性地增加1（_Incref_nz()），并返回一个指向同一资源的 shared_ptr。
      • 若 _Uses == 0（资源已释放），则返回一个空的 shared_ptr。
    • 这个过程使用了比较并交换（CAS） 等原子操作来保证线程安全。
  • enable_shared_from_this：其内部持有一个 weak_ptr。当 shared_ptr 构造时，会检测并初始化这个 weak_ptr，从而安全地生成管理 this 的 shared_ptr。

🚀 std::unique_ptr：独占所有权的轻量级方案

unique_ptr 的设计目标是零开销，其大小通常与裸指针相同。

  • 核心实现：继承自 _Unique_ptr_base 基类。关键在于使用 _Compressed_pair 来存储其两个核心成员：
    • 被管理的原始指针。
    • 删除器 (Deleter) 对象。
  • 空基类优化 (EBO)：当删除器是空类（如默认的 std::default_delete）时，_Compressed_pair 会通过继承空删除器的方式，使其不占用额外空间。因此，使用默认删除器的 unique_ptr 大小与裸指针完全相同。
  • 移动语义：unique_ptr 是 move-only 类型，其拷贝构造函数和拷贝赋值运算符被显式删除 (= delete)。所有权通过移动语义（std::move）来转移。
  • 数组特化：MSVC 为 std::unique_ptr<T[]> 提供了偏特化版本。这个版本提供了 operator[] 来访问数组元素，并默认使用 delete[] 来释放内存。
  • 自定义删除器：支持自定义删除器，但删除器的类型会作为模板参数。如果使用有状态的删除器或函数指针，会因需要存储而增加 unique_ptr 对象的大小。

⚖️ 关键区别一览

特性 std::shared_ptr std::unique_ptr
所有权 共享 (Shared) 独占 (Unique)
拷贝语义 可拷贝，引用计数+1 不可拷贝 (move-only)
内存开销 较大 (控制块 + 原子操作) 较小 (通常与裸指针相同)
删除器 不作为模板参数，类型擦除 作为模板参数
线程安全 引用计数操作是线程安全的 无额外线程安全保证

理解这些源码级别的实现细节，能帮助你更好地理解其行为、开销以及适用场景，从而写出更高效、更健壮的 C++ 代码。
